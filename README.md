# pg-txmode

Safe PostgreSQL through **transaction-pooling proxies**: Cloudflare Hyperdrive first, with PgBouncer in transaction mode and Supavisor as the same class of proxy.

A transaction pooler hands your next statement to whichever server connection is free. Anything that lives in a *session* (`SET`, session advisory locks, `LISTEN`, named prepared statements, `WITH HOLD` cursors, `PRESERVE ROWS` temporary tables) then belongs to nobody, and nothing reports the mistake. pg-txmode makes those facts explicit, testable and hard to get wrong:

- a **catalogue** of where a pooled connection differs from a direct PostgreSQL connection, as one data file with a source and a way of verifying for every cell (below, generated from it);
- a **typed connection mode** with a capability record, so a client built for a pooled mode has no session-only API;
- **safe SQL constructs** (row locks, `ON CONFLICT` claims, conditional `UPDATE`, outbox, `SET LOCAL`, isolation levels, whole-transaction retry, per-transaction timeouts), each with an executable test against PgBouncer;
- a **harness** that starts PostgreSQL and PgBouncer and runs a probe suite, so a session-state leak fails a test instead of production;
- a **SQL lint** on the PostgreSQL parser's own AST, over source files and over a recorded statement log.

The core has no dependency on Effect or on any one driver. Adapters are thin.

Status: in development. Specs 0000 to 0005 are merged; spec 0006 (the npm release path) is in review. Nothing is published to npm yet.

## Where a pooled connection is not a direct one

Each cell is `outcome (how it is known)`. `docs`: a primary source says so (the links). `pgbouncer-probe`: a probe of this repository's harness observed it against PgBouncer 1.25 in transaction mode, with a direct PostgreSQL connection as its control. `hyperdrive-probe`: a probe observed it through Hyperdrive; the only recorded run is another project's deployed Worker ([evidence](docs/evidence/hyperdrive/vektorprogrammet-reimagined-0000-results.md)), because this repository's probe Worker needs Cloudflare credentials ([wizard](docs/wizard/hyperdrive-probe.md)). `unverified`: neither documented nor measured here. Outcomes: `works`, `scoped` (only for the transaction or statement), `leaks` (succeeds and shows to other clients, no error), `unsupported`, `breaks`, `degrades`, `differs`, `unknown`.

## Develop

Needs [devenv](https://devenv.sh) (Bun, Node 24, gitleaks, PostgreSQL 18, PgBouncer 1.25).

```sh
devenv shell -- bun install
devenv shell -- bun run ready      # every gate, including the harness against a real PgBouncer
devenv shell -- bun run probes     # the probe matrix, printed
devenv shell -- bun run docs:gen   # regenerate the table above after editing the catalogue
devenv up                          # a PgBouncer and PostgreSQL on fixed ports for your own client
```

[`AGENTS.md`](AGENTS.md) describes the process (spec, code, PR, one to one) and the gates.

## Release

Not published yet. When it is, the packages `@pg-txmode/core`, `@pg-txmode/pg`, `@pg-txmode/effect` and `@pg-txmode/lint` are versioned together (`0.1.0-alpha.N`, dist-tag `alpha`) and installed with `npm i @pg-txmode/core@alpha`: `@alpha` always installs the newest alpha. A plain `npm i @pg-txmode/core` (the `latest` tag) is not managed: the registry sets `latest` on a package's first publish and nothing here moves it, so it may install `0.1.0-alpha.0` and not the newest alpha. `npm view @pg-txmode/core dist-tags` shows both. `devenv shell -- bun run release:stage` builds `packages/<name>/dist`, the directory that is published ([spec 0006](docs/specs/0006-release.md)). The harness is not published.

## Roadmap

Planned only unless marked built.

1. Spec 0000: development lifecycle and scaffold (built, merged).
2. Spec 0001: the core, the harness and the lint (built, merged).
3. Spec 0002: the `pg` (node-postgres) adapter (built, merged).
4. Spec 0004: the outbox delivers at least once (lease, token, fenced ack; built, merged). Replaces the at-most-once relay of spec 0001.
5. postgres.js adapter: Cloudflare's page says `prepare: false` hangs there, the Supabase page says pipelining breaks; a probe settles which.
6. Spec 0003: `@pg-txmode/effect`, a `SqlClient` and a transaction door for Effect, built on `@effect/sql-pg` and configured from the connection mode (built, merged). It is the only package that depends on Effect, and it reproduces and avoids the `@effect/sql-pg` hang of the research report (M2b). Drizzle `effect-postgres` and Effect `SqlModel` on top of it: planned.
7. A deployed Hyperdrive probe Worker, the only source of Hyperdrive truth. It needs the operator's Cloudflare credentials, so the steps are a [wizard](docs/wizard/hyperdrive-probe.md), not a script anyone runs for them.
8. Spec 0006: the npm release path (stage step, Changesets in pre mode `alpha`, a Release workflow with a `check` mode and a hold; built, in review). Nothing is published until the operator lifts the hold: see [`docs/specs/0006-release.md`](docs/specs/0006-release.md).
